  <name>Task 1: Create core schema migration</name>
  <files>supabase/migrations/20260122000001_core_schema.sql</files>
  <action>
    Create comprehensive schema migration with all tables. Follow these principles from research:
    - Use UUID primary keys (gen_random_uuid())
    - Reference auth.users for user identity
    - Include workspace_id on tenant-scoped tables
    - ON DELETE CASCADE for proper cleanup
    - created_at/updated_at timestamps on all tables
    - Enable RLS immediately after each CREATE TABLE
    
    Tables to create (in order):
    
    1. **profiles** - User metadata (auto-created on signup)
       - id (uuid, PK, references auth.users)
       - email, full_name, avatar_url
       - created_at, updated_at
    
    2. **workspaces** - Organizations/teams
       - id (uuid, PK)
       - name, slug (unique)
       - created_at, updated_at
    
    3. **workspace_members** - Join table for workspace access
       - id (uuid, PK)
       - workspace_id (references workspaces)
       - user_id (references auth.users)
       - role (owner/admin/member)
       - unique(workspace_id, user_id)
    
    4. **apps** - Products within workspace
       - id (uuid, PK)
       - workspace_id (references workspaces)
       - name
       - api_key_hash (hashed, not plain text)
       - created_at, updated_at
    
    5. **boards** - Feedback organization
       - id (uuid, PK)
       - workspace_id, app_id (both reference parents)
       - name, description
       - is_default (boolean)
    
    6. **feedback_status** - Enum-like table for statuses
       - id (uuid, PK)
       - workspace_id
       - name (Open, Under Review, Planned, In Progress, Complete)
       - position (for ordering)
    
    7. **feedback** - Core feedback items
       - id (uuid, PK)
       - app_id (references apps)
       - board_id (optional, references boards)
       - status_id (references feedback_status)
       - type (Bug, Feature Request, UI/UX)
       - title, description
       - submitter_id (references auth.users, nullable for SDK submissions)
       - submitter_email, submitter_name (for SDK-passed identity)
       - vote_count (denormalized)
       - metadata (jsonb for device info)
       - created_at, updated_at
    
    8. **votes** - Upvotes on feedback
       - id (uuid, PK)
       - feedback_id (references feedback)
       - user_id (references auth.users)
       - unique(feedback_id, user_id)
    
    9. **comments** - Discussion on feedback
       - id (uuid, PK)
       - feedback_id (references feedback)
       - user_id (references auth.users)
       - content (text)
       - created_at, updated_at
    
    10. **subscriptions** - Follow feedback for updates
        - id (uuid, PK)
        - feedback_id (references feedback)
        - user_id (references auth.users)
        - unique(feedback_id, user_id)
    
    Also create:
    - Trigger function handle_new_user() to auto-create profile
    - Trigger on auth.users AFTER INSERT
    - Helper function is_workspace_member(workspace_id uuid) returns boolean
    - Helper function is_workspace_admin(workspace_id uuid) returns boolean
    - Indexes on all foreign key columns and frequently queried columns
  </action>

    - handle_new_user trigger function exists

    - Indexes created on workspace_id, app_id, user_id columns

<task type="auto">
  <name>Task 2: Create RLS policies migration</name>
  <files>supabase/migrations/20260122000002_rls_policies.sql</files>
  <action>
    Create comprehensive RLS policies for all tables. Follow research patterns:
    - Always use `to authenticated` role
    - Wrap auth.uid() in select: `(select auth.uid())`
    - Use is_workspace_member() helper for workspace-scoped tables
    - Create policies for SELECT, INSERT, UPDATE, DELETE where appropriate
    
    Policies by table:
    
    **profiles**:
    - SELECT: Users can view any profile (public)
    - UPDATE: Users can only update their own profile
    
    **workspaces**:
    - SELECT: Members can view workspaces they belong to
    - INSERT: Any authenticated user can create (becomes owner)
    - UPDATE: Only admins/owners can update
    - DELETE: Only owners can delete
    
    **workspace_members**:
    - SELECT: Members can view membership of their workspaces
    - INSERT: Admins/owners can add members
    - UPDATE: Admins/owners can change roles
    - DELETE: Admins/owners can remove members
    
    **apps**:
    - SELECT: Workspace members can view
    - INSERT: Admins/owners can create
    - UPDATE: Admins/owners can update
    - DELETE: Admins/owners can delete
    
    **boards**:
    - SELECT: Workspace members can view
    - INSERT/UPDATE/DELETE: Admins/owners only
    
    **feedback_status**:
    - SELECT: Workspace members can view
    - INSERT/UPDATE/DELETE: Admins/owners only
    
    **feedback**:
    - SELECT: Workspace members can view all feedback for their apps
    - INSERT: Allow from authenticated users OR via service role (SDK)
    - UPDATE: Admins/owners can update status, board assignment
    - DELETE: Admins/owners only
    
    **votes**:
    - SELECT: Anyone can see votes on visible feedback
    - INSERT: Authenticated users can vote on visible feedback
    - DELETE: Users can remove their own vote
    
    **comments**:
    - SELECT: Anyone can see comments on visible feedback
    - INSERT: Authenticated users can comment
    - UPDATE: Users can edit their own comments
    - DELETE: Users can delete own, admins can delete any
    
    **subscriptions**:
    - SELECT/INSERT/DELETE: Users manage their own subscriptions
  </action>
  <verify>
    - Migration file contains CREATE POLICY for each table
    - All policies use `to authenticated` role
    - auth.uid() wrapped in (select ...) for performance
    - is_workspace_member() used for workspace-scoped access
    - is_workspace_admin() used for admin-only operations
  </verify>
  <done>Complete RLS policy set for multi-tenant isolation</done>
</task>
